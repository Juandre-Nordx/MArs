# v0.2.2.2 — Automatic oxygen and road access

Oxygen pipes now use the same automatic cardinal-side connection rules as water pipes. A live segment directly beside any edge of an oxygen-capable building's full footprint connects it. There is no extra connector charge. Diagonal proximity or a gap does not connect. Power retains its explicit north-side port.

All oxygen contacts on one building share an internal manifold. Branches touching different sides merge before resource allocation, so a tank and its oxygen reserve appear only once. Removing or disabling one contact preserves supply while another remains; removing the final contact disconnects the building. No stored oxygen is created, moved or lost just because connections change.

Roads already detected adjacent footprint edges in the simulation. This update makes their inspector and selection markers use actual contacts on any side instead of presenting a north-side-only port. Every adjacent road component is listed when a building has several access routes. Separate roads on opposite sides remain separate components: vehicles do not route through a building footprint. Existing road artwork includes the physical building approach stubs.

Citizen oxygen advice now explains automatic side connections. Building connection markers and overlay selection reflect the same shared connection helper. Walkers and buggies prefer a directly adjacent road entrance. A pending buggy can still unload at its original valid building edge if a new preferred road entrance is added during travel. Consumption, immigration eligibility and construction/refund costs are unchanged.

## Compatibility

Gameplay schema remains 4; network rules advance to version 3. Existing rule versions 1 and 2 migrate by rebuilding derived components under the new rules. Buildings, infrastructure, residents, pending buggies, physical stores and aggregate resources are preserved, with no free pipes or supplies. Older schema compatibility is retained. No SQL migration is required. Dockerfile, Compose, Prisma schema and Railway configuration are unchanged.

The display/API release is `0.2.2.2`; private npm workspace metadata uses valid SemVer `0.2.2+2`. The lockfile updates version metadata only, without dependency upgrades.
