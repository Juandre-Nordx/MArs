# V0.3.1 Phase 1 — Large-world support and map migration

This is the first verified implementation pass of the [supplied V0.3.1 requirements](V0.3.1-REQUIREMENTS.md). It is a prerelease (`0.3.1-phase.1`), not the completed industrial expansion. The baseline was inspected: the existing React/Phaser game, survival economy, original buildings, population/buggies, construction, paid infrastructure and automatic utility contacts were present. Mining, scanning, industrial inventories and factories were absent and have not been advertised as operational.

## Implemented

- Shared 512×512 logical tile bounds, global tile coordinates and 16×16 chunk coordinates. Isometric projection and camera pan/zoom are preserved. Coordinate navigation and a return-to-colony button make distant locations reachable without dragging across the map.
- Deterministic per-chunk terrain. Original 20×20 textures, shades and decorative positions remain exactly as before for each seed. Outside that area, seeded regions add plains, crater fields, rocky highlands and ice-bearing terrain with distinct palettes/details. Surface decoration remains traversable.
- Viewport-based chunk graphics: offscreen chunks are destroyed, visible explored chunks are batched into graphics, and entirely unknown chunks use one fog polygon without generating terrain tiles. Buildings, infrastructure sprites and animated people/buggies are culled with a viewport margin. Camera movement never changes simulation or reveals fog.
- Sparse saved exploration indexed by chunk and local tile. The original 400 tiles start explored. Construction and new infrastructure in unexplored terrain are rejected. The map overview distinguishes explored chunks and the current location. Survey-driven exploration is not yet implemented.
- Seed-defined surface/subsurface deposits, generated lazily when a chunk is materialised. Deposits store identity, mineral, position, depth, richness, initial/remaining finite reserves, extraction technology and independent discovery status. Repeated exploration preserves their exact records; revealing terrain does not reveal or replenish minerals. No deposits are added to inventory.
- A minimal registry of the ten requested geological minerals. A guaranteed nearby deposit cluster at tiles 21–27,24 supplies future iron/aluminium/copper/lithium/silicon/carbon/ice chains across all seeds, outside existing buildings and infrastructure. Uranium is rare in general generation. CO₂, hydrogen, oxygen and methane are not mineral deposits. Deposit discovery UI/scanning is still pending.
- Schema 5 and map generator/expansion version 1. Schema-4 saves upgrade without relocating buildings, roads, pipes, cables, residents or pending buggies, or changing inventory. Schema 1/2/3 migrations remain supported. Loading schema 5 retains saved chunk/deposit records, including depleted reserves. Derived utility networks still rebuild under network rules 4.
- Heap-backed A\* ground routes retain road preference. Accessibility validation floods the occupied bounding area with an exterior margin rather than an empty whole world. Immigration continues entering through the original landing staging perimeter, so a larger map does not turn existing arrivals into 512-tile journeys. Existing in-flight paths remain saved.

## Verification and performance

Run from the repository root:

```sh
npm run build
npm test
npm run lint
npm run format:check
PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH=/usr/bin/chromium npm run test:e2e -- --workers=1
npm run benchmark:world
```

Final validation passed: production build, **97 unit tests**, **16 Chromium browser tests**, lint, formatting and `git diff --check`. The browser suite completed in 1.9 minutes. The benchmark budgets passed.

The world unit tests cover seed/order independence, all four regions, exact original terrain preservation, partial exploration, hidden deposits, reserve persistence, starter resources across 50 seeds, schema-4 migration/idempotence, distant placement and infrastructure, invalid saves, projection/culling and 1,022-step paths. Prior economic/conservation tests remain in the suite. Browser tests exercise far-map fog/navigation, camera return, bounded rendering of a fully explored world, offscreen sprite culling and reserve preservation across save/reload.

Initial Node benchmark in this managed environment (100 buildings, 1,024 explored chunks, 1.65 MB JSON save):

| Operation                                   | Measured time | Automated ceiling |
| ------------------------------------------- | ------------: | ----------------: |
| Generate all 262,144 terrain tiles          |      19.71 ms |          5,000 ms |
| Materialise full-world exploration/deposits |      13.79 ms |          5,000 ms |
| Paid construction in the spread-out colony  |     260.39 ms |          5,000 ms |
| 1,000 fixed ticks with 100 buildings        |     275.02 ms |          5,000 ms |
| Validate/load the fully explored save       |     134.00 ms |          5,000 ms |
| Unobstructed 1,022-step path                |       1.27 ms |          1,000 ms |

Viewport tests cap the supported 1366×768 minimum-zoom view at 64 chunks/16,384 terrain cells, versus 262,144 logical tiles. These are work/time budgets, not a measured GPU frame-rate guarantee. Fully explored state is deliberately a stress fixture: gameplay currently explores only the starter area. The benchmark fixture supplies extra building instances for load measurement; it is not a game command or resource grant.

## Remaining release work

Continue in the prescribed order, verifying each pass:

1. Deposit inspector, geological overlay and configurable surface/subsurface/deep scanning.
2. Survey drones, dispatcher, batteries/charging, pathfinding failure recovery and exploration.
3. Mines and real reserve depletion.
4. Cargo rovers, finite local inventories, storage and real material transfer.
5. Refining, then battery/solar manufacturing with input-funded recipes.
6. Industrial ice extraction, melting, purification and connection to existing water supplies.
7. Hydrogen/methane synthesis, resource-isolated pipelines and storage.
8. Abstract nuclear fuel, maintenance and safe shutdown generation.
9. Cryogenic propellants, launch deliveries and fuel contracts.
10. Industrial dashboards, balancing, larger fleet/network performance and Railway release preparation.

The complete battery chain, methane production, industrial water extraction and nuclear power acceptance criteria are **not yet met**. Existing construction remains immediate and other cargo retains its prior shared-inventory abstraction until the logistics phase. Utility topology already caches between edits, but fine-grained incremental graph updates and drone routing caches remain later performance work. Terrain graphics are batched; sprite pools are not introduced for the small existing actor fleet.

Two verification issues were resolved: viewport sprite lists initially used stale camera bounds after coordinate jumps, and test collection stalled when projection helpers imported a second copy of the simulation package. Culling now keys off the actual camera world view; projection reads a small shared dimensions module. The final full suite passes with the normal test command.

No SQL migration is needed for the versioned JSON game state. Docker, Compose, Railway configuration and Prisma schema are unchanged. No production deployment was performed. Full Docker/Prisma verification remains subject to the existing Prisma engine download restriction; no live Railway credentials were available. The Phaser bundle size advisory remains. This phase must not be presented or deployed as completed V0.3.1.
