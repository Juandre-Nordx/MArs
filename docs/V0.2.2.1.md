# v0.2.2.1 — Colonist conversations and automatic water hookups

Extends the merged v0.2.2 game. Both requests in this release are implemented together.

## Talk to a colonist

Click a suited person on the map to select them and open their conversation in the inspector. A ring follows the selected resident. Picking uses the displayed/interpolated sprite body, works with pan/zoom, and remembers the person pressed even if they walk away before mouse release. Dragging remains camera movement; construction modes retain their placement controls. The Resident roster also provides accessible **Talk to Colonist N** buttons. Close, Escape, clicking terrain/buildings, or loading/starting a colony clears the conversation. Simulation continues unless explicitly paused.

Residents use original Mars-colony dialogue with distinct deterministic phrasing. Their **Content**, **Concerned** or **Distressed** outlook derives from actual current conditions: assigned operational housing, their own reachable water/oxygen reserves, home electricity, shared food and route availability. Positive topics can be expanded to see their quote/evidence. Immediate personal concerns and practical colony advice are shown separately, with real quantities and connection/status evidence.

Examples: an occupied home and dependable water/oxygen/food can make a resident content, while all beds being occupied prompts a conditional suggestion to add a supplied home for newcomers. A disconnected home complains about its missing connection even when a remote tank contains water. Fixing that connection updates the conversation immediately. Empty/low reserves, power faults, stalled producers and insufficient housing produce specific actionable comments.

`packages/simulation/src/feedback.ts` performs this read-only assessment. It does not add a random happiness percentage, hidden personal history, a new persistent morale system or resource/production modifiers. Opening a conversation never changes consumption, stores or population. Classic city-builder interaction is the inspiration; all dialogue is original.

## Automatic water connections

A water-using/storage/producing building automatically connects when a live water pipe is on a tile directly beside **any cardinal edge of its full footprint**. This includes the far edges of multi-tile farms and the Starship. No extra connector placement or resource charge is needed beyond constructing the pipe itself. A one-tile gap or diagonal proximity does not connect; pipes still cannot occupy building footprints. Oxygen and power retain explicit north-side ports.

All water contacts on one building join through its internal manifold. The graph engine merges branches touching different sides before calculating pools and allocations, so a tank is included only once. Connectivity changes preserve physical tank contents and aggregate inventory; they do not create water or construction materials. Removing one contact keeps a connection alive if another remains. A building loses its connection only when its last live contact is removed, broken or disabled. Production/storage enable flags retain their existing operational rules.

Connection markers, pipe end artwork, overlay components, the network inspector, citizen feedback and buggy eligibility all use the actual new connectivity. The inspector identifies the real automatic contact rather than always displaying the old north port.

## Saves and release metadata

Gameplay schema remains **4**. Network rules advance from **1 to 2**, with an explicit load migration for existing version 4 saves. The migration rebuilds derived graphs under the new rules while preserving buildings, residents/routes, the buggy, infrastructure, physical stores, credits, population and time. No pipes or supplies are granted. Older schema 1/2/3 compatibility paths now produce rules version 2 as well. Future unknown rule versions are rejected. New saves require the new rules-aware client.

No SQL migration is needed. Prisma schema, Dockerfile, Compose and Railway configuration are unchanged. Display/API release label is `0.2.2.1`; private npm workspace versions use the valid SemVer equivalent `0.2.2+1`. The lockfile changes release metadata only; no dependencies were upgraded.

Production workspace build, 71 unit tests, lint and formatting checks passed. Browser validation covers the previous nine checks, citizen clicking/roster/pan/zoom, live water-repair feedback and a moving-target click (all 12 checks passed together). Unit tests cover accurate positives/concerns, local rather than global utility access, all four water-contact sides, multi-tile edges, gap/diagonal rejection, multi-branch tank conservation and old-rule migration.

Full Docker/Prisma integration and live Railway rollout remain unverified under the existing environment restrictions; no production service or database was modified. The advisory Phaser bundle-size warning remains.
